## 1. Introduction & Objectives
This Test Plan outlines the testing strategy for the User Registration and Login modules of the Alison online learning platform. The objective is to verify that registration and login processes function correctly, safely prevent unauthorized entries, maintain data integrity, and offer an intuitive experience for end-users.

## 2. Scope of Testing
### In-Scope
* **Functional testing** of the User Registration flow (valid entries, edge cases, error handling).
* **Security testing** of duplicate registration prevention.
* **Functional testing** of the Login interface (valid credentials, incorrect passwords, empty states).
* **Verification** of 'Remember Me' checkboxes for returning users.

### Out-of-Scope
* Performance, load, or stress testing.
* Payment gateway integrations or course enrollment flows.

## 3. Testing Strategy & Methodology
**Manual Black-Box testing** will be utilized to execute scenarios outlined in the test case specifications. Testing encompasses functional, negative, boundary value analysis, and boundary-condition UI verification.

## 4. Environment & Tools
* **Testing Environment:** Production (Live website)
* **Supported Platforms:** 
  * Windows 11 (Google Chrome)
  * Web – Android (Google Chrome)
  * Alison Mobile App
* **Tracking Artifacts:** 
  * Microsoft Word (Test Plan)
  * Microsoft Excel Spreadsheet (Test Cases)
  * Microsoft Word (Bug Logs)

## 5. Pass/Fail Criteria
* **Pass:** System behaves precisely as written in the expected results column.
* **Fail:** Discrepancies emerge between actual UI/functional behavior and expectations.
